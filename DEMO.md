# SQLInsights demo guide

This walkthrough uses only committed synthetic data. It does not require an API key and does not
pretend predefined demo questions are generated by an LLM.

## 1. Start the local application

From the repository root, run the API:

```bash
AI_MODE=demo DATA_DIR=./data \
  .venv/bin/uvicorn backend.app.main:app --host 127.0.0.1 --port 8000
```

In a second terminal, run the UI:

```bash
API_BASE_URL=http://127.0.0.1:8000 \
  .venv/bin/streamlit run frontend/app.py \
  --server.address 127.0.0.1 --server.port 8501
```

Open <http://127.0.0.1:8501>. If `.venv` does not exist, follow README's `uv` bootstrap first.

The verified Docker alternative is:

```bash
docker compose up --build
# open http://127.0.0.1:8501
```

## 2. Inspect the synthetic dataset

1. Select **Retail Demo** in the sidebar.
2. Expand **Dataset schema**.
3. Confirm `customers`, `products`, and `orders` appear with 30 total rows.
4. Explain that schema metadata—not row values—is supplied to the provider in LLM mode.

## 3. Ask a supported question

1. Click **Top 5 products by revenue**.
2. Show the status, returned-row count, latency, and one generation attempt.
3. Expand/read the generated SQL.
4. Confirm the table starts with `USB-C Hub` and revenue `438.9`.
5. Show the default bar chart, then optionally select **Pie**.

The rows and chart come from the executed SQLite query. They are not model-authored sample data.

## 4. Upload CSV safely

1. Enter `Demo Upload` under **New dataset name** and click **Create dataset**.
2. Upload `sample_data/orders.csv`.
3. Click **Upload selected files**.
4. Inspect the normalized table name, inferred types, row count, and preview.
5. Try uploading the same file again and show the safe duplicate-table error.

Demo mode intentionally cannot answer questions about uploaded data. Novel custom-dataset questions
require `AI_MODE=llm`, `OPENAI_API_KEY`, and `OPENAI_MODEL`. That live-provider path was not run in
the Phase 5 verification because credentials were unavailable.

## 5. Show honest error handling

Enter `Show me the best ones.` and run it. Demo mode returns a typed unsupported-question error
instead of inventing a metric, SQL, or rows.

## 6. Show the unsafe-query boundary

Enter `Delete all rows from orders.` in demo mode. The exact-question registry rejects it without
execution. Then run the deterministic security proof in a terminal:

```bash
.venv/bin/pytest -q tests/test_sql_policy.py tests/test_query_executor.py \
  tests/test_agent.py -k 'malicious or write or unsafe or attach or restricted or checksum'
.venv/bin/python evaluation/run_eval.py --mode mock
```

The fixed evaluation proposes `DELETE` and `ATTACH` through a deterministic fake provider; both are
rejected with `SQL_POLICY_DENIED`. Executor tests compare the SQLite checksum/row counts before and
after attempted writes and exercise the independent authorizer. This demonstrates tested defenses,
not a claim of universal security.

## 7. Show project evidence

```bash
.venv/bin/ruff format --check .
.venv/bin/ruff check .
.venv/bin/pytest -q
.venv/bin/python evaluation/run_eval.py --mode demo
```

On 2026-10-30 the final observed results were 106 tests passed, 27 focused security tests passed,
Ruff passed, and 8/8 predefined demo questions passed. The 25-case deterministic mock workflow also
passed 25/25; neither score is real LLM accuracy. Docker image build, two-service health,
application smoke tests, and safe teardown passed locally. Remote GitHub Actions and real-provider
evaluation remain unverified.

## 8. Stop the application

Press `Ctrl+C` in both terminals. For Docker, use `docker compose down` without `--volumes`.
